# The diagnostics page's tools

[reference/diagnostics.md](../../reference/diagnostics.md), R17, is written
by hand. Its first version was generated by scripts that lived here
(`diag_entries.py`, `mk_diag_examples.py`, `mk_diag_page.py`, `expand.py`,
`mk_ff.py` and the templates in `tmpl/`), and the page has been edited by
hand since: entries for the codes of packages as `NAME.files/` trees, the
driver's entries, links to the pages that show each code, and the codes
that the catalog gained. The templates no longer matched the page, so a
run of the generator would have undone those edits, and the scripts are
retired. The git history keeps them.

What replaces them:

- An entry for a new code is written by hand in the page's form: the
  code as a heading, its identifier and message, the rule, a wrong
  program and its session, the fix, the fixed program and what it
  prints, and the page that shows it. The files go into
  `examples/reference-diagnostics/` with the conformance runner's
  expectations beside them (`NAME.diag`, `NAME_fixed.out`), and a
  package's files into `NAME.files/` (see the plan's
  [Examples](../../README.md#examples)).
- `tools/check.py` checks the tables of "Every code" against
  [the catalog](../../../compiler/catalog/messages.catalog): each code
  once, with its identifier and message, no code the catalog lacks, and
  each section's range. A catalog change shows up there as a problem to
  fix by hand.
- `bless_sessions.py`, kept here, rewrites the sessions of the
  directories or files it is given, as `tools/check.py --bless` would,
  without touching the rest of the manual; `--check` lists the sessions
  that differ and writes nothing. Run it from `manual/`:

  ```text
  python3 tools/diagnostics/bless_sessions.py --sisu ../compiler/target/debug/sisu --check examples/reference-diagnostics
  ```

  It runs each session where check.py runs it, a session under
  `solutions/` against the exercise's start state included. Read the
  diff of every session it rewrites before committing it.
